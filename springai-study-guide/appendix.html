A.0Spring AI 1.x → 2.0 破坏性变更速查表

这是全站最应该打印出来贴在显示器旁的一页。 2.0 是架构级重构，下面每一行都是"照抄旧代码会出问题"的地方。左列是 1.x 的写法，右列是 2.0 的正确写法。

一、底座与依赖

项1.x2.0
Spring Boot3.x4.0 / 4.1（与 3.x 不兼容，不能混用）
Spring Framework6.x7.0，Jakarta EE 11
Java17+17+（官方支持到 26）。
Java 21 只是从源码构建 Spring AI 时的要求，不是运行时要求
JacksonJackson 2Jackson 3（包名 com.fasterxml.jackson → tools.jackson，日期序列化默认行为也变了）
RAG Advisor 模块spring-ai-advisors-vector-storespring-ai-vector-store-advisor（改名）
MCP 传输模块 groupIdio.modelcontextprotocol.sdkorg.springframework.ai
MCP Java SDK0.18.x1.0.x 起（随 2.0.0 发布）
已移除的模块Azure OpenAI / openai-sdk / OCI GenAI / Vertex / CosmosDB / Hanadb移出主仓库，改由厂商或外置仓库维护
模型供应商（核心）十几种，各自实现收敛为 7 家：OpenAI、Anthropic、Bedrock、Google GenAI、Mistral、DeepSeek、Ollama。
OpenAI / Anthropic / Google 改用厂商官方 SDK
不再内置的供应商智谱 AI、Azure OpenAI、OCI、Vertex智谱需引其独立仓库；Azure OpenAI 并入 spring-ai-openai；MiniMax 走 Anthropic 兼容协议

二、工具调用（改动最大的一块）

项1.x2.0
执行循环在哪 藏在每个 ChatModel 实现内部，无法干预 ToolCallingAdvisor，Advisor 链中的一等公民，可观察、可组合、可替换
关闭自动执行 .internalToolExecutionEnabled(false)
属性 spring.ai.*.chat.internal-tool-execution-enabled		 两者都已删除。改用：
单次 → .advisors(AdvisorParams.toolCallingAdvisorAutoRegister(false))
全局 → spring.ai.chat.client.tool-calling.enabled=false
函数式工具注册 裸 Function bean + .toolNames("name")
（SpringBeanToolCallbackResolver 按名字解析）		 toolNames() 已删除。必须注册显式 ToolCallback：
FunctionToolCallback.builder(name, fn).inputType(X.class).build()
FunctionCallback存在已彻底移除（1.0 起由 ToolCallback 取代）
ToolCallAdvisor类名改名为 ToolCallingAdvisor
Advisor 数量约束无链中只能有一个 ToolAdvisor，重复注册直接报错
工具调用次数上限无（可无限调用）默认生效：单工具 40 次 / 合计 150 次，可用 spring.ai.tools.limits.* 调整
工具解析回退默认开启默认关闭：只有请求里显式附带的工具可执行（安全默认值）
@Tool 方法可见性有约束放宽：public / package-private / private、静态或实例方法都可
工具 span 名tool_call <名>execute_tool <名>；gen_ai.operation.name 从 framework 改为 execute_tool
★ 按 span 名配的告警规则会静默失效，升级后必须回归

三、结构化输出

项1.x2.0
校验与重试 自己写 try/catch + 重试 + 把错误回喂模型 .entity(X.class, spec -> spec.validateSchema())
框架自动带错误信息重试，默认最多 3 次
厂商原生约束 无统一入口 spec.useProviderStructuredOutput()：把 schema 作为 API 级约束发给厂商，比写在提示词里硬
BeanOutputConverter有 postProcessSchema(JsonNode) 扩展点该扩展点已移除；schema 生成改由 JsonSchemaGenerator，会带 OpenAPI 风格 format 提示
可选字段判定Kotlin 可空字段会被当必填已修正；@JsonProperty(required=false) 也不再算必填

四、会话记忆

项1.x2.0
conversationId 有默认值（ChatMemory.DEFAULT_CONVERSATION_ID = "default"），忘了传会静默混用 必填。.param(ChatMemory.CONVERSATION_ID, id) 缺失或传 null 立刻抛 IllegalArgumentException；该常量已删除
Advisor builder.conversationId("x")该方法已删除，改为每次调用传参
PromptChatMemoryAdvisor存在（省 Token，信息有损）整个类被移除，统一用 MessageChatMemoryAdvisor
默认顺序常量DEFAULT_CHAT_MEMORY_PRECEDENCE_ORDER = HIGHEST_PRECEDENCE + 1000改为 + 200；ToolCallingAdvisor 在 + 300
默认记忆在工具循环之外，看不到中间工具消息
JDBC 记忆表结构靠 timestamp 排序新增 sequence_id BIGINT 列与索引（MySQL 时间戳精度只到秒，同秒消息排序不确定）。旧库需回填
替代方案—社区项目 spring-ai-session 用事件溯源重做记忆，支持全部消息类型与自动压缩，计划 2.1 替换内置实现

五、配置与 Options

项1.x2.0
.options 层级 spring.ai.openai.embedding.options.model 已移除：spring.ai.openai.embedding.model
范围：embedding / image / audio / moderation / OCR。chat 层仍保留 .options
Ollama 思考开关spring.ai.ollama.chat.think-optionspring.ai.ollama.chat.think
Options 可变性 有 setter、copy()、*Options#fromOptions() 严格不可变，必须用 builder；改值用 .mutate()。
集合返回不可修改视图，改它抛 UnsupportedOperationException
Options 合并ModelOptionUtils.merge()移到 ChatClient 层：ChatClient.Builder#combineWith()
ChatModel 取默认选项getDefaultOptions()弃用，改 getOptions()
默认 temperature模型实现里内置默认值默认值被移除，需要时显式配置，否则可能报错或行为变化
OpenAI 默认模型gpt-4o 系列默认改为 gpt-5-mini，依赖隐式默认值的代码行为会变
JSON 工具类ModelOptionsUtils 的 JSON 方法、JsonParser 改用 JsonHelper / JacksonUtils / JsonSchemaUtils

六、MCP

项1.x2.0
服务端注解用 @Tool 暴露@McpTool / @McpToolParam / @McpResource / @McpPrompt / @McpComplete，注解扫描自动注册
注解包路径org.springaicommunity.mcp.annotation.*org.springframework.ai.mcp.annotation.*
默认传输SSEStreamable HTTP（SSE 已 deprecated，STDIO 用于本地）
客户端配置写法外部 JSON + servers-configurationspring.ai.mcp.client.stdio.connections.<名>.command/args
工具是否自动可用较宽松不会自动注册到 ChatClient，必须显式传 SyncMcpToolCallbackProvider 给 .tools() / .defaultTools()
服务端入参校验默认关闭默认开启，失败返回 isError=true；用 validateToolInputs(false) 关闭
暴露面控制—新增 McpToolFilter bean；spring.ai.mcp.server.expose-mcp-client-tools
安全与观测需自己接内置 Micrometer span / OpenTelemetry 指标；OAuth 2.0 与 API Key 通过 mcp-security 项目

七、2.0 新增、值得专门学的三个能力

① 渐进式工具披露

ToolSearchToolCallingAdvisor。工具上百个时不再全量塞给模型， 而是给它一个 toolSearchTool 按需检索。
官方实测省 34%~64% token，准确率无可测下降。 加 starter + 一行配置即可启用（第 7 章）。

② 结构化思考

AugmentedToolCallbackProvider + AgentThinking。 给工具 schema 动态追加 innerThought 字段， 模型调工具时顺便把推理填进来，你的代码拿到的是类型安全对象， 不用再从回复文本里用正则抠（第 9 章）。

③ 可组合的循环钩子

继承 ToolCallingAdvisor 重写 doInitializeLoop / doBeforeCall / doAfterCall / doFinalizeLoop， 就能实现审批门、预算闸、事件推送，不必推翻整个循环（第 9 章）。

迁移决策建议（一句话版）：
  • 新项目 / 教学项目 → 直接 Spring Boot 4.1 + Spring AI 2.0，没有历史包袱。
  • 存量 Boot 3.5.x 项目 → 先评估 Boot 4 的迁移成本（Boot 3.5 与 Framework 6.2 已于 2026-06-30 EOL）， 在迁移完成前继续用 Spring AI 1.1.x 维护版本。
  • 只想小修小补 → 留在 1.1.x，不要为了追新强行迁移。

报错关键词章节原因与解决
No qualifying bean of type 'ChatModel'1缺 starter 或 api-key 为空导致自动配置未生效

JsonParseException: Unexpected character3模型用 ```json 包裹了输出，或前面有解释文字。提示词明确「只输出 JSON」

检索结果大量重复4重复灌库，灌前先 delete(filter) 做幂等

熔断一直不恢复6下游真故障，需人工介入检查密钥/配额/网络

模型不使用工具7描述太模糊 / 模型不支持 function calling / 工具太多（>15）
模型用错工具7工具职责重叠，合并或在描述里写「不要用于……」
工具异常导致 5007配 DefaultToolExecutionExceptionProcessor.alwaysThrow(false)

MCP 工具列表为空8缺 ToolCallbackProvider bean，或 toolcallback.enabled=false

Agent 死循环9没设最大步数；加重复调用检测
Agent 卡住不动9工具返回空或异常，模型无法判断下一步；返回要带明确状态
确认接口「编号不存在」9待确认操作存在内存里，重启丢了 → 持久化
Zipkin 看不到 trace10采样率 0 / 端点地址错 / 缺依赖三者之一
Prometheus 内存暴涨10指标标签基数过高（放了 userId/query），删掉高基数标签
MDC 里 traceId 串了10finally 里没 MDC.remove()
容器内连不上数据库11用了 localhost，必须用 compose 里的 service 名
应用启动时数据库连接失败11用 depends_on: condition: service_healthy 等依赖真正就绪
容器日志时间差 8 小时11容器默认 UTC，加 tzdata 并设置 Asia/Shanghai

A.6术语表

术语解释
LLMLarge Language Model，大语言模型。本课程的「模型」默认指它
Token模型的计费与长度单位。中文约 1 字 ≈ 0.7~1 token。输入输出都计费
Prompt提示词。一次请求的完整输入，包含消息列表与参数
System / User / Assistant Message消息的三种角色：规则设定 / 用户输入 / 模型输出
Temperature采样温度 0~2。越低越确定（抽取、分类用 0），越高越发散（创作可 0.8+）
Context Window上下文窗口。一次请求能容纳的最大 Token 数（含输入输出）
Embedding嵌入。把文本转成高维向量的过程；语义相近的文本向量距离也近
向量维度向量的长度（如 1536）。必须与模型一致，且换模型必须重灌
余弦相似度只比较向量方向、忽略长度的相似度度量。文本检索的标准选择
ANN / HNSW / IVF近似最近邻及其常用索引结构。用少量召回率损失换取数量级的速度提升
Chunk文本切分后的片段。RAG 中向量化的基本单位
RAG检索增强生成。先检索资料再让模型基于资料回答
TopK检索返回的最相似结果条数
Similarity Threshold相似度阈值。低于它的检索结果被丢弃，是防幻觉的关键参数
Rerank重排。对初步召回的结果做二次精排，提升精度
Hybrid Search混合检索。向量检索 + 关键词检索（BM25）合并结果
Tool Calling工具调用。模型输出「调用意图」，由你的代码真正执行
Function Calling工具调用的另一种叫法（模型侧的机制名）
MCPModel Context Protocol。把工具标准化的协议，支持跨进程跨语言
Agent智能体。能自主决定多步执行的程序（模型 + 工具 + 循环 + 刹车）
ReActReason + Act。思考→行动→观察的循环范式
Planner规划器。先出完整步骤清单再执行
HITLHuman-in-the-loop。人工确认环节，高风险操作必做
AdvisorSpring AI 的切面机制，用于日志、记忆、RAG、限流等横切逻辑
Observation / Span / Trace可观测性概念：一次操作 / 链路中的一个环节 / 一条完整链路
LLM-as-a-Judge用模型给模型输出打分，用于效果评估
Faithfulness（忠实度）回答是否有资料支撑的度量，是查幻觉的核心指标
幻觉 Hallucination模型编造看似合理但错误或不存在的信息
提示词注入用户通过输入试图覆盖系统指令的攻击方式
越权访问了当前身份无权访问的数据或功能
幂等同一个请求执行多次与执行一次效果相同。写操作必须幂等
降级 Degradation主能力不可用时，退回到一个仍可用的替代方案
熔断 Circuit Breaker失败率过高时主动拒绝请求，给下游恢复时间
脱敏日志/数据中隐藏敏感信息（手机号、身份证、密钥）
