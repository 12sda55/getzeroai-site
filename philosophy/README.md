## 二、为什么用生成器

**问题**：顶栏、侧边栏、页脚导航在 13 个页面里完全相同。
如果手写 13 份 HTML，每次调整导航（比如改一个章节名、加一个链接）
就要改 13 处 —— 漏改一处的后果是导航不一致，而且很难被发现。

**做法**：把外壳统一在 `_src/gen.py` 里，正文放在 `_src/*.part`（只有正文，不含导航）。
改导航只需要改 `gen.py` 一处。

**产出是标准静态 HTML** —— 没有构建产物、没有运行时依赖、没有框架。
任何静态托管都能直接用。生成器只是"写这些 HTML 的方式"，不是运行时的一部分。

### 修改流程

```bash
cd D:/wx/philosophy-ai-guide

# 1. 改正文 → 编辑 _src/chXX.part（注意：不要改 .html，会被覆盖）
#    改导航/章节名/版本戳 → 编辑 _src/gen.py

# 2. 重新生成
python _src/gen.py

# 3. 校验（标签配对 / 锚点 / 死链 / 版本戳 / 行尾符 / 相对路径）
python _src/check.py
```

### 内容版本戳（重要约定）

`gen.py` 里的 `VERSION` 常量控制所有页面页脚的版本戳：

```python
VERSION = "2026-09-21 10:00"
```

**每次更新内容都要改这一行并重新生成。** 它是判断"用户看到的是否为最新"的唯一可靠依据 —— 
浏览器缓存、CDN 缓存、看错地址都会造成"更新了却看不到"，有版本戳就能立刻分辨。
样式在 `assets/style.css` 的 `.footer .ver`。

## 三、部署前的注意点

### 1. 404 页的链接前提

`404.html` 用的是**站点根绝对路径**（`/index.html`），因为 404 页会在任意路径层级被触发 ——
用相对路径 `index.html` 会被解析成 `/foo/index.html` 而二次 404。

**前提是站点部署在域名根目录**（如 `https://philosophy.example.com/`）。
如果要部署到子目录（如 `https://example.com/philosophy/`），
需要把 404 里的三个链接改成带子目录前缀的形式。

### 2. 上传时排除 _src/

`_src/` 是源文件，不需要上传：

```bash
# 打包时排除
--exclude "_src/*"
```

### 3. 缓存策略（如果部署到 OSS / S3）

**对象存储默认不给对象设 `Cache-Control`**，浏览器会启用启发式缓存并长时间不回源 —— 
这是"更新了却看不到"的头号原因。上传时显式加上：

```
Cache-Control: no-cache
```

配 `no-cache` 后浏览器每次发条件请求：内容变了才重下，没变返回 304。兼顾正确性与开销。

### 4. 相对路径

站点为纯静态，页面间**只能使用相对路径**（`ch01.html`、`assets/style.css`）。
`check.py` 的第 7 项会检查这一点。

## 四、内容约定

- **每章统一结构**：学习目标卡 → 概念详解（含哲学家/思想实验卡片）→
  **工程锚点**（这个哲学概念在 AI 里的具体位置）→ 反面意见 → 动手练习 →
  延伸阅读 → 自测题（可折叠）→ 验收标准
- **每个哲学概念都要落到一个具体的技术判断上**，不做泛泛的思想史介绍。
  看到紫色虚线框是思想实验，左右分栏是「哲学 → 工程」映射卡。
- **书单只写能确认的信息**：以英文原名 + 作者 + 年份为主，中译本仅在能确认译者时标注。
  不写不确定的出版社 —— 一个错误的出版社名会让学生白找很久。
- **不给超出证据的结论**：涉及尚无定论的问题（如 AI 是否有意识），
  明确标注"当前无法被实验判定"，并说明争论双方各自在什么立场上。
- 行尾符统一 LF。
